## Overview

**Generative SNUPI** harnesses **diffusion-based generative modelling**—the paradigm currently redefining protein engineering—to advance **DNA-origami design**. 
> Trained on a curated dataset of **450 equilibrium conformations DNA Origami structures** generated by the multiscale **SNUPI** simulator, the framework learns structural priors and outputs **strand-level designs** that faithfully realise user-specified geometries and functional goals

## Features

- **Multi-format Input Support**: SVG, PLY, STL, and PT files
- **Conditional Generation**: Generate designs from target shapes
- **Automated Routing**: Converts coordinates to complete design files
- **Routing Repair (optional)**: Target-Guided Adaptive Vertex Repair (TGAVR) fixes generated designs that the router cannot route, without retraining
- **Multiple Output Formats**: CanDo, BILD, oxDNA, PDB, and PyTorch tensors
- **GPU Acceleration**: CUDA support for faster generation

## Installation

### Prerequisites

- **OS**: Linux (Ubuntu 20.04+ recommended) — Windows is **not preferred** due to NVTX dependencies and Linux-specific CUDA library paths
- **GPU**: NVIDIA GPU with compute capability ≥ 7.5 (Turing, Ampere, Ada, Hopper, **Blackwell / RTX 50xx**)
- **Driver**: NVIDIA driver ≥ 570 (supports CUDA 12.8). No system-wide CUDA toolkit is needed — the CUDA runtime libraries are installed inside the conda environment
- **Conda** (Anaconda / Miniconda / Miniforge)

Check your GPU and driver with:

```bash
nvidia-smi --query-gpu=name,compute_cap,driver_version --format=csv
```

| Component | Version | Source |
|-----------|---------|--------|
| Python | 3.10 | conda-forge |
| PyTorch | 2.8.0 + CUDA 12.8 | pip (`download.pytorch.org/whl/cu128`) |

Notes:

- **DGL / PyTorch version warning** — DGL 2.4.0 is the final DGL release and is officially built for PyTorch ≤ 2.4, which does not support RTX 50xx GPUs. Its CUDA kernels run correctly with PyTorch 2.8, so `pip check` reports `dgl 2.4.0+cu124 has requirement torch<=2.4.0, but you have torch 2.8.0+cu128`. This warning is expected and harmless.
- **`setuptools<70`** is pinned because DGL 2.4 imports `setuptools.extern`, which was removed in newer setuptools.
- **`PYTHONNOUSERSITE=1`** is set inside the environment so packages from `~/.local/lib/python3.x` cannot override the pinned versions.
- Only the compiled PyG extension that the code uses (`torch-cluster`, for `radius_graph` / `knn_graph`) is installed. `torchvision`, `torchaudio`, `torch-scatter`, `torch-sparse` and `torch-spline-conv` are not needed.

To update an existing environment after `environment.yml` changes:

```bash
conda env update -n generativeSNUPI -f environment.yml --prune
```

## Usage

### Conditional Generation

Generate DNA origami designs from target shapes:

```bash
# SVG files
python run_sampling.py --target_shape Flower_Logo.svg --num_samples 5 --design_scaffold_length 2000 --device cuda

# PLY files (2D/3D meshes)
python run_sampling.py --target_shape 01_triangle.ply --num_samples 3 --design_scaffold_length 600 --device cuda

# PT files (preprocessed tensors)
python run_sampling.py --target_shape Circle.pt --num_samples 4 --device cuda
python run_sampling.py --target_shape Monalisa_v1.pt --num_samples 10 --device cuda --no_plots
```

### Routing Repair (optional)

Some generated designs cannot be routed: at vertices and junctions, where several duplexes meet, the
router may leave a staple longer than 50 bp, find no valid nick, or fail on badly paired helix ends.
**TGAVR** (Target-Guided Adaptive Vertex Repair) is an optional step in front of the router. It:

- aligns the target shape to the generated coordinates and repairs defective vertex regions;
- makes small, bounded edits to helix-end lengths (at most a few % of the base pairs), judged by
  the router's own stages;
- post-processes three router steps without changing the geometry: staple splitting, conflicting
  staple crossovers, and single-strand pairing at junctions.

It is **enabled by default**, and the original routing always runs first. Only a design that the
original routing cannot route validly (an exception, or a staple longer than 50 bp) is repaired
and routed again. A design that already routes is exported exactly as before. The diffusion model,
the router modules and the scaffold sequences are not modified.

`run_sampling.py` passes `--target_shape` to the routing automatically. To route an existing
design:

```python
from routing import route_generated_design

# routing with TGAVR (default; recommended configuration, up to 15 routing calls)
route_generated_design("generated_designs/<folder>/<design>.pt",
                       target_shape="Miura_ori_4x4_40PercentFolded_best.pt")

# original routing only
route_generated_design("generated_designs/<folder>/<design>.pt", enable_tgavr=False)
```

| Argument | Description | Default |
|----------|-------------|---------|
| `enable_tgavr` | Repair designs the original routing fails on | `True` |
| `target_shape` | Target used to generate the design: a `.ply` / `.stl` / `.pt` path or a file name in `target_shapes/`. With `None`, vertex repair is skipped and the router-guided repairs still run | `None` |
| `tgavr_config` | `automated_design.tgavr.TGAVRConfig`, e.g. `TGAVRConfig.recommended(max_routing_attempts=5)` | `TGAVRConfig.recommended()` |
| `tgavr_seed` | Router seed used during the repair | `0` |

`route_generated_design_batch` accepts the same arguments.

Notes:

- The design is routed from the repaired coordinates. They are saved as `<name>_tgavr_coords.pt`
  when they differ from the input.
- Every repair and routing attempt is written to `<name>_tgavr.json`.
- A warning is printed when the scaffold is longer than 7560 nt (the longest scaffold sequence
  shipped). This depends on the design size, not on the repair.

## Input/Output

### Input Files

| Format | Description | Location |
|--------|-------------|----------|
| **SVG** | Vector graphics | `target_shapes/svg/` |
| **PLY** | 3D mesh files | `target_shapes/ply/2D/`, `target_shapes/ply/3D/` |
| **STL** | 3D model files | `target_shapes/stl/` |
| **PT** | Preprocessed tensors | `target_shapes/pt/` |

### Output Structure

```
generated_designs/design_name_YYYYMMDD_HHMMSS/
├── design_name_sample_001.pt      # Generated coordinates
├── design_name_sample_001.cndo    # CanDo design file
├── design_name_sample_001.bild    # Chimera visualization
├── design_name_sample_001.dat     # oxDNA configuration
├── design_name_sample_001.top     # oxDNA topology
├── design_name_sample_001.dat.pdb # PDB structure file
├── design_name_sample_001_mean.pt # PyTorch mean data
├── design_name_sample_001_seq.pt  # PyTorch sequence data
├── design_name_sample_001_tgavr.json        # TGAVR report (only if the design was repaired)
└── design_name_sample_001_tgavr_coords.pt   # repaired coordinates (only if TGAVR changed them)
```

### File Usage

- **`.cndo`**: Load in CanDo software for design analysis
- **`.bild`**: Visualize in Chimera/ChimeraX
- **`.dat/.top`**: Molecular dynamics simulations with oxDNA
- **`.pdb`**: Structural analysis in VMD, PyMOL, or Chimera
- **`.pt`**: Machine learning analysis with PyTorch and Simulate with SNUPI

### Command Line Arguments

#### Required Parameters

| Parameter | Description | Default |
|-----------|-------------|---------|
| `--num_samples` | Number of samples to generate | 2 |
| `--design_scaffold_length` | Scaffold length for SVG/PLY/STL files | 7249 |

### Design Parameters

- **Scaffold Length**: Controls target shape complexity (2000-7249 bp optimal)
- **Device**: Use `cuda` for GPU acceleration

## Troubleshooting

### RTX 50xx (Blackwell): `sm_120 is not compatible` / GPU hangs

RTX 50xx GPUs need PyTorch ≥ 2.7 built with CUDA ≥ 12.8. Older builds (e.g. the legacy PyTorch 1.13.1 + CUDA 11.7, or PyTorch ≤ 2.6) have no `sm_120` kernels, so a simple CUDA operation either hangs or fails with `no kernel image is available`. Recreate the environment from `environment.yml`:

```bash
conda env remove -n generativeSNUPI
conda env create -f environment.yml
```

### `ModuleNotFoundError: No module named 'setuptools.extern'` when importing DGL

DGL 2.x imports `setuptools.extern.packaging`, which newer setuptools no longer provides. `environment.yml` already pins it; in a manually built environment run:

```bash
pip install "setuptools<70"
```

### `CUDA out of memory` on large shapes

Large targets need several GB of free GPU memory (e.g. `Monalisa_v1.pt` allocates ~8 GB in one step). Check `nvidia-smi` for other processes using the GPU and stop them, or generate fewer samples at a time. Setting `PYTORCH_CUDA_ALLOC_CONF=expandable_segments:True` can help with fragmentation.

### CUDA Library Compatibility (Legacy CUDA 11.7 install)

This applies to the **legacy CUDA 11.7** install only. If your system has a CUDA version newer than 11.7 (e.g. CUDA 12.x or 13.x), DGL may fail to load with an error like:

```
OSError: libcusparse.so.11: cannot open shared object file: No such file or directory
```

This happens because DGL 1.1.2+cu117 requires `libcudart.so.11.0`, `libcublas.so.11`, and `libcusparse.so.11`, which are bundled inside the conda environment but not on the default library search path. To resolve this, add the paths to these libraries (typically found under `$CONDA_PREFIX/lib` and the `nvidia/` subdirectories inside your environment's `site-packages`) to `LD_LIBRARY_PATH`.
